# Patient uterus anatomy studio

The separate `#uterus-model` patient page defaults to an original schematic learning model. The team-supplied single-mesh FBX remains reachable in Original model; its internal structures are not labelled or morphed into gestational stages.

Built: six labelled parts (fundus, myometrium, endometrium, cervix, tubes and ovaries); OrbitControls damping/inertia; optional slow rotation that pauses on touch; key/fill/rim lighting; hotspot camera glides; open clipping-plane cutaway; transparent wall; a manually advanced guided tour; optional illustrative muscle motion; keyboard orbit and zoom/reset; bilingual fixed Charon narration with visible text, mute and explicit device-voice fallback; reduced motion, low-bandwidth opt-in, retry and route/visibility cleanup. Fullscreen retains SOS and an exit control.

The geometry is simplified original teaching content, not a validated anatomical asset, patient image or measurement. The open clipping surface is not a tissue-thickness measurement or surgical simulation. Surface markers on the illustrative ovaries are not measured follicles. The small rhythmic motion is not a contraction waveform, timing tool or assessment. Growth/cycle/involution simulations and physiological heat maps require a separate clinically reviewed model before implementation.

Educational references: [Cleveland Clinic uterus anatomy](https://my.clevelandclinic.org/health/body/22467-uterus), [CDC female reproductive system](https://www.cdc.gov/cancer/cervical/amigas/toolbox/pdf/female-reproductive-system-508.pdf). Both language versions and the geometry still need clinical review before a clinical/public rollout; this work does not assert review has happened.

Narration uses the existing `/api/tts` handler and its cache/rate limits. `shared/uterus-learning.js` provides a fixed public catalogue: no patient record, camera data or free-form question is sent to Gemini. The voice is forced to Charon for this catalogue. Provider failures keep the text visible and offer explicit device voice; they never silently switch voices.

Validation: `node --test backend/pregnancyMirror.test.js backend/dayaSpeech.test.js`; `NODE_PATH=/tmp/dai-browser/node_modules node scripts/test-uterus-studio-browser.cjs`. The browser script uses an isolated fixture and mock prepared WAV speech at 1440, 1024 and 390 pixels, verifies actual cutaway canvas changes, six part controls, narration/mute, original FBX fallback, reduced motion, keyboard navigation, Hindi/dark layouts, no page exceptions, failed-import retry and route cleanup. Use `DAI_TEST_WEBKIT=1` with an installed Playwright WebKit browser for the Safari-engine run. Real-device input, exact anatomical proportions and clinician content review remain separate evaluations.

Blank-panel recovery: the patient shell previously used cache-first lookup by pathname, allowing stale dashboard HTML to coexist with uncached new viewer code. The studio now loads its public anatomy dependency on demand when absent, catches mounting failures, offers visible retry, and also reacts to delegated sidebar navigation. Shell v99 prefers current public shell files online (five-second fallback), preserves offline cached access, and keeps API/upload paths outside its cache. Added `backend/patientShellCache.test.js` verifies online replacement, versioned paths, offline fallback and API/upload exclusion. Browser checks deliberately block the catalogue, verify visible recovery/retry, and test actual WebKit sidebar navigation when the initial dependency is missing. No offline record, encryption key or consent storage is deleted by this shell update.
